# Skills

个人 Agent Skills 集合,适用于 Claude Code 及其他支持 [Agent Skills](https://skills.sh) 规范的 AI 编码工具。

## 安装

```bash
npx skills add StreetCornelia/skills
```

## Skills 列表

### steelman — 双向钢人论证

面临选择、决策,或想深度检验一个想法时,不直接给答案,而是分两轮走完一个结构化的论证流程:

1. **问题重述**:用最完整、最有力的方式重述你真正想解决的问题(字面问题往往不是真正的问题)
2. **双向钢人**:分别为支持和反对你当前想法的一方,给出各自最强的论证——强到持该立场的人会觉得被公正代表
3. **分歧与关键变量**:点破双方真正的分歧(通常在价值排序、风险偏好或假设,而非事实),列出最可能翻转结论的关键变量
4. **唯一的关键问题**:只问一个信息增益最大的问题,等你回答后,才给出明确判断、理由和可执行的下一步行动

适合"要不要 / 该不该 / A 还是 B / 这个想法靠谱吗"这类带倾向的决策场景。涉及不可逆决策时,会在行动步骤里强制加入低成本的可逆验证。

### dialog-map — 对话脑图与决策记录

把对话里最先消失、又最难重建的东西留下来:代码在 git 里、文件在磁盘上,只有"为什么走这条路、否决了什么、依据的约束是什么"随上下文窗口一起蒸发。本 skill 增量维护一份 `.claude/dialog-map.md`:

- **脑图**(Mermaid mindmap):管结构,节点带状态标记 `✓` 已定 / `✗` 已否决 / `?` 待决 / `!` 约束,被否决的节点保留不删
- **决策记录**:管"为什么",每条含决定、理由、否决了哪些备选、以及**失效条件**(什么变化会让这个决定需要重审)
- **待决问题 / 压缩时间线**:未解的悬置项,以及已入图段落收敛成的一行摘要

增量更新:靠文件顶部的"更新水位"只处理新内容,多次触发不产生重复节点。筛选标准只有一条——它会随上下文消失且未来会被再次需要吗?执行流水和礼节性往返不记,宁可空也不灌水。

触发时机以 `/compact` **之前**和开新会话继续同一主题时**先读它**价值最高。附三种 Claude Code hook 接法(每 N 轮提醒 / 压缩前落盘 / 新会话读回)与计数脚本,见 [references/auto-trigger.md](dialog-map/references/auto-trigger.md)。

### sub-agent — 子 Agent 编排

强制把当前请求的实际执行工作交给子 Agent 完成,主 Agent 只做编排者(拆分、调度、协调、验收、汇总),不亲自执行实质性任务:

- 任务可拆分时,默认启动多个子 Agent 并行执行(调查、实现、测试、审查、方案比较)
- 子任务指令必须自包含:完整上下文、绝对路径、边界、输出契约,不依赖主对话的指代
- 每个子 Agent 有清晰、互斥、可验收的职责;共享文件按所有权划分或用 worktree 隔离,避免写入冲突
- 只有存在真实输入依赖时才串行;结果不达标时由原子 Agent 补救、修正指令重派或另派子 Agent 复核,失败不静默降级
- 用户指定的编排方案(数量、分工、模型、顺序)始终优先于默认策略
- 规则与具体工具解耦,附 Claude Code 等环境的机制映射

通过 `$sub-agent` 显式调用,或明确要求本次任务采用子 Agent 模式时触发。
