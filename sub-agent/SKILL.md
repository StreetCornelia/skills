# Sub Agent

将主 Agent 作为编排者，把实际任务交给一个或多个子 Agent 完成。主 Agent 负责拆分、调度、协调、验收和汇总，不自行替代子 Agent 完成实质性任务。

## 强制规则

1. 至少启动一个子 Agent。即使任务很小或不可拆分，也必须由一个子 Agent 执行实际工作。
2. 先判断任务是否能够拆成彼此独立或低耦合的工作单元。能够拆分时，默认启动多个子 Agent 并行执行。
3. 优先并行处理互不依赖的调查、实现、测试、审查、资料整理或方案比较；只有存在真实输入依赖时才串行。
4. 不为制造并行而重复分配同一任务。每个子 Agent 必须有清晰、互斥、可验收的职责。
5. 用户明确指定的编排方案优先，包括子 Agent 数量、任务分工、先后顺序、模型、推理强度、交付物和是否允许嵌套委派。
6. 遵守当前环境的并发槽位、工具权限和安全限制。任务数超过可用并发时，分批并行调度。
7. 如果子 Agent 能力不可用或无法启动，立即说明阻塞原因，不得静默改为主 Agent 独立执行。

## 编排流程

### 1. 解析用户约束

提取目标、交付物、完成标准、范围、依赖与用户指定的子 Agent 编排要求。用户没有指定编排时，使用以下默认流程。

### 2. 判断可拆分性

满足任一条件时，视为可拆分：

- 存在两个及以上互不依赖的模块、文件、数据源或研究方向。
- 调查、实现、测试、审查可以由不同子 Agent 独立推进。
- 多个候选方案可以并行分析后再比较。
- 一个主任务包含可独立验收的多个交付物。

只有当任务是单一原子操作、所有步骤存在严格连续依赖，或拆分协调成本明显高于收益时，才使用单个子 Agent。

### 3. 分配子任务

为每个子 Agent 提供：

- 明确目标和范围。
- 必要上下文、路径、输入与约束。
- 不得触碰的边界，避免与其他子 Agent 冲突。
- 预期输出和验收标准。
- 与其他子任务的依赖关系。

涉及共享文件写入时，按文件或模块划分所有权。无法隔离写入范围时，让一个子 Agent 负责修改，其他子 Agent 只做只读分析、测试或审查。

### 4. 并行执行与协调

一次启动所有当前无依赖且并发槽位允许的子任务。主 Agent 在子 Agent 工作期间只执行编排职责，包括提供补充上下文、解除阻塞、收集进度和安排下一批任务。

需要串行时，在上游子 Agent 产出可用结果后，再将必要结果传给下游子 Agent。不要让下游依赖未完成或未经确认的假设。

### 5. 验收与补救

检查每个子 Agent 的结果是否满足范围、证据和验收标准。发现缺口时，优先让原负责的子 Agent 补充；需要独立验证时，分配另一个子 Agent 复核。不得由主 Agent 悄悄补做实质性内容。

### 6. 汇总交付

主 Agent 可以整合、去重和组织子 Agent 已完成的结果，并向用户给出一个自洽的最终答复。说明关键结论、完成状态、验证结果和仍存在的阻塞；无需逐条暴露内部调度过程，除非用户要求。

## 默认角色划分

根据任务选择最小且有效的角色集合，不固定套用：

- **调查 Agent**：定位事实、代码路径、资料或约束。
- **执行 Agent**：实现修改或生成主要交付物。
- **验证 Agent**：运行测试、检查结果或做独立复核。
- **比较 Agent**：分别分析不同候选方案。

如果任务只有一个不可拆分的工作单元，只启动一个执行 Agent；主 Agent仍只负责协调和最终交付。
